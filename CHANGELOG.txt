[2026-06-12] Centre-rectangle fix: zero fade caused permanent tile stacking
-----------------------------------------------------------------------------
The last aesthetic bug: at low zooms a centre rectangle of slightly
different texture/hue. Mechanism (read from mapbox-gl-dev.js source):
with raster-fade-duration 0, Tile#registerFadeDuration computes
fadeEndTime = timeAdded + 0 < now and EARLY-RETURNS without setting
fadeEndTime. SourceCache#update treats undefined fadeEndTime as "still
fading" forever and permanently retains every loaded DESCENDANT of every
ideal tile; the painter draws descendants on top (stencil prefers
higher-res). High-zoom imagery (different vintage/colour grading) was
therefore permanently stacked in the screen centre at low zooms.

CHANGED  lib/createMaps.ts — set _supportsFading = false on every source
         cache (same private-API patch block as the cache-size override).
         Skips the fade-retention machinery entirely; with zero fade there
         is nothing to fade, and edges keep instant full vibrancy.
         Live-verified: in-use tile set at low zoom is now the ideal level
         only (was a 15-level stack).


[2026-06-12] ROOT CAUSE FOUND: Mapbox clamps tile cache to ~40 tiles
----------------------------------------------------------------------
Verified by playing live (preview browser + tile-state dumps): Mapbox
hard-clamps every source's tile LRU to viewportTiles×5 (≈40 tiles) inside
SourceCache#updateCacheSize. The maxTileCacheSize option is Math.min'ed
against that and can only SHRINK the cache. Consequence: EVERY warming
strategy in this saga worked correctly and was then silently evicted within
seconds — warmed tiles re-fetched mid-animation (HTTP cache, 100-400 ms
decode window) appearing as mixed-vintage tile rectangles / soft edges.

CHANGED  lib/createMaps.ts — override SourceCache#updateCacheSize (private
         API, verified against mapbox-gl 3.24, re-verify on upgrade) on
         style.load to pin the cache at tilesPerLevel × 16 levels × 1.3.
         Live-verified: LRU holds the full pyramid; previously-broken zoom
         ranges render flawlessly edge to edge.
CHANGED  components/GameMap.tsx
         - Fixed warm-sequencing bug: areTilesLoaded() was checked

[2026-06-12] Real raster fade knob found: raster-fade-duration paint prop
---------------------------------------------------------------------------
CHANGED  components/GameMap.tsx
         - The Map-level fadeDuration option only governs SYMBOL fading —
           raster tile fade is the raster LAYER's `raster-fade-duration`

         - Drift reduced: ±10° lng / ±6° lat → ±3° / ±2°.


[2026-06-12] Dark edge ring fixed: fade removed, cache scales with screen
---------------------------------------------------------------------------
CHANGED  components/GameMap.tsx
         - fadeDuration 300 → 0. Root cause of the dark/desaturated edge
           tiles: Mapbox fades EVERY raster tile in from transparent when it
           enters the render set — including warmed, cached tiles. At the
           expanding edge of a zoom-out nothing renders beneath the fading
           tile, so the fade painted a dim ring at the screen edges for the
           entire animation. Screen centre never shows it (old-level tiles
           render beneath = true cross-fade). With the pyramid fully
           preloaded, fade serves no purpose: cached tiles appear at full
           vibrancy on the frame the camera reveals them. Fade was only ever
           needed for late network arrivals, which the ladder eliminated.
           Side benefit: ladder steps no longer wait out fades → faster
           loading screen.
         - maxTileCacheSize: fixed 1536 → computed from canvas size at map
           construction ((w/256+2)·(h/256+2) × 14 levels × 1.3 margin).
           The pyramid scales with the viewport; the fixed value silently
           re-introduced eviction (black edges) on large/4K windows.
           ~1 270 tiles on 1080p, ~3 400 on 4K, ~440 on a phone.

[2026-06-12] Half-zoom preload ladder + delayed smaller drift
---------------------------------------------------------------
CHANGED  components/GameMap.tsx
         - Preload ladder moved from integer zooms to HALF zooms (15.5 …
           4.5). Root cause of edge load-in: raster sources round fractional
           zoom to pick the tile level, so just below each integer (e.g.
           z14.6 → level-15 tiles) the viewport is up to ~41% wider than
           that level's own snapshot — the integer ladder never cached that
           outer ring. z = N − 0.5 is the widest viewport level N is ever
           shown at, so that is where each level is now preloaded.
         - Drift shrunk (4–9% of width, 3–7% of height; was 10–25% / 8–20%)
           and delayed: animation is now two chained easeTo halves split at
           the z11 spline knot (t = 0.5 → 10 s). First half is a pure
           centred zoom-out; the offset rides only on the second half, so
           drift is imperceptible until ~10 s in. Each half replays its half
           of the same Catmull-Rom spline — combined zoom trajectory is
           identical to the single-easeTo version, seam included.
         - driftTimerRef guards the phase-2 starter: cleared on round reset,
           unmount, and when frozen goes true (guess made before 10 s would
           otherwise let the pending phase-2 easeTo yank the result camera).
         - maxTileCacheSize 300 → 512 (half-zoom viewports cache more tiles
           per level; all 13 levels must stay resident through the 20 s).

[2026-05-29] Shake fix + Play Again
-------------------------------------
CHANGED  components/GameMap.tsx — replaced rAF + jumpTo() animation with a
